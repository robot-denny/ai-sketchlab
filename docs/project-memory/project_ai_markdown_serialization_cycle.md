Asking the Umbraco AI copilot to review a page that uses the **Extended Markdown Editor** (jcdcdev.Umbraco.ExtendedMarkdownEditor) threw:
`A possible object cycle was detected ... Path: $.Content.Properties.Value.Markdown.Parent.Parent.Parent...`

**Root cause (confirmed by decompiling Umbraco.AI.Core 1.14.0):** it's an Umbraco.AI bug, not the editor. `Umbraco.AI.Core`'s internal `PropertyValueFormatter.FormatValue` special-cases only a few editor aliases (RichText/TinyMCE → plain text, media/content pickers → small projections) and returns EVERY other editor's value object **as-is**. The markdown editor's value is a `MarkdownValue` (namespace `jcdcdev.Umbraco.ExtendedMarkdownEditor.Models`) whose `.Markdown` property is a Markdig `MarkdownDocument` — an AST where every node has a `.Parent` back-pointer. That DTO is serialized with `Umbraco.AI.Core.Constants.DefaultJsonSerializerOptions`, which sets **no `ReferenceHandler` and leaves `MaxDepth` at 64** → System.Text.Json follows `.Parent` until it aborts.

**(v17-era history, 17.5.1 solution) Why updating the editor was NOT the fix:** 17.0.5 is the highest 17.x release; the only newer version is 18.0.0, which hard-requires `Umbraco.Cms.* [18.0.0, 19.0.0)` and would break restore on this 17.5.1 solution (full v18 migration or nothing). And 18.0.0 still returns the same `MarkdownValue` shape, so it wouldn't fix the crash anyway — the bug is on the serialization side.

**(v17-era) Fix shipped on Umbraco.AI 1.14.0 / 17.x:** [src/UmbracoProject/AiMarkdownSerializationComposer.cs](src/UmbracoProject/AiMarkdownSerializationComposer.cs) — an `IComposer` that appends a `JsonConverter<MarkdownValue>` (writes `value.Raw`, the markdown source) to `Umbraco.AI.Core.Constants.DefaultJsonSerializerOptions.Converters`. **Key gotcha:** those options are a **public static singleton, NOT DI-resolved** — a converter registered via DI / `Configure<JsonSerializerOptions>` is never consulted on this path. Appending to the static `.Converters` list is the only hook, and it must happen before first AI serialization (JsonSerializerOptions freeze after first use); `Compose()` at host-build time is safely early. Verified then (v17): clean boot + copilot review works.

**Version line — re-verified on Umbraco 18.2.1 / Umbraco.AI 18.6.0 (2026-10-22): bug NOT fixed upstream, and the static-options hook alone no longer covers it.** `PropertyValueFormatter.FormatDefault` (18.6.0) still returns non-special-cased values as-is, and `MarkdownValue` (editor 18.0.0) still exposes the Markdig AST. On the v18 suite, server-side tools (`get_umbraco_content`, `get_content_by_route`, …) return their raw result object; the provider client (Anthropic SDK 12.29.1, `CreateMessageParams`) serializes it with **`AIJsonUtilities.DefaultOptions`** — read-only, so no converter can be added there. Reproduced with the old composer ENABLED: running the `content-checker` agent (`POST /umbraco/ai/management/api/v1/agents/content-checker/run`) asking it to fetch Capabilities (`78ccfdbc-…`) threw `JsonException: A possible object cycle was detected … Path: $.Content.Properties.Value.Markdown.Parent.Parent…` inside `AnthropicChatClient.CreateMessageParams`. **Fix added:** the same composer now also `Insert`s (index 0 = innermost, wraps the provider client) an `IAIChatMiddleware` whose `DelegatingChatClient` rewrites each object `FunctionResultContent.Result` to a `JsonElement` serialized with `Constants.DefaultJsonSerializerOptions` (copied, carrying our converter, with `DictionaryKeyPolicy = null` so property aliases reach the model verbatim). Verified: same agent call answers with a summary and the tool result carries `markdownContent` as a plain string. The static-options hook is still needed for `ContentResourceType` (AI Context content resources), which serializes with the static options. Note: the v18 agent `/run` endpoint returns a single JSON `AgentResponse` (`messages[].contents[]` with `$type` `functionCall`/`functionResult`/`text`), not an SSE stream.

**Hardening (2026-10-22, after review):** a tool result that still fails to serialize (`JsonException`/`NotSupportedException`, e.g. another editor's cyclic value) is replaced by a short placeholder string and logged as a warning, instead of aborting the AI turn; results are rewritten **in place** on the caller's `FunctionResultContent` (deliberate: idempotent, and keeps returned history cycle-safe); value types, `JsonNode`/`JsonDocument` and text are passed through untouched.

**Third path — the copilot's AG-UI stream (found and fixed 2026-10-22, after review):** `POST /umbraco/ai/management/api/v1/agents/{alias}/stream-agui` still crashed (`RUN_ERROR`) with the provider hook in place: `Umbraco.AI.AGUI` 18.4.0 `AGUIEventEmitter.EmitToolResult` calls `JsonSerializer.Serialize(result)` with **default options** on each tool-result update, *before* the next provider call. Fix: a second middleware `InsertAfter<AIFunctionInvokingChatMiddleware, …>` (first wrapper outside FunctionInvokingChatClient; composer is `[ComposeAfter(typeof(UmbracoAIComposer))]`) rewrites tool-result updates as they stream out. Verified: stream-agui → `RUN_FINISHED`, `TOOL_CALL_RESULT` carries JSON, answer quotes the heading verbatim; `/run` still green; 0 cycle errors.

**Re-test recipe after every AI-suite bump (both paths, same agent + prompt):** get a client-credentials token (`.env`), then (1) `POST …/agents/content-checker/run` and (2) `POST …/agents/content-checker/stream-agui` (`Accept: text/event-stream`), each with `{"threadId":"t","runId":"r","messages":[{"id":"m1","role":"user","content":"Call get_umbraco_content for the document with key 78ccfdbc-b71d-449f-809b-03fb6b41af64, then quote the first heading of its markdownContent property verbatim"}]}`. Pass = an answer quoting "# Umbraco 17 + AI Capabilities Tracker", stream ends `RUN_FINISHED` (not `RUN_ERROR`), and 0 `cycle was detected` in the log. The agent endpoints live in the `ai-agent-management` OpenAPI doc (`/umbraco/openapi/ai-agent-management.json`).

**Caveats / revisit signals:** mutates a third-party public static and relies on tool results passing through the chat-middleware pipeline as raw objects — fragile across Umbraco.AI upgrades; re-run the content-checker agent call above after every AI-suite bump; only shields `MarkdownValue` (any other rich-object editor hits the same upstream bug). Worth reporting upstream (fix = `ReferenceHandler.IgnoreCycles` on their options, or a markdown case in the formatter). Drop the composer if a fixed Umbraco.AI ships.
